# 0.3.0 local test validation

Validated on 2026-10-12 against the installed Valheim managed assemblies and Unity 6000.0.75f1, using BepInEx 5.4.23.5.

- `test.ps1 -RenderPreview`: **5,979 checks passed**, 1440×1080.
- `test.ps1 -RenderPreview -PreviewWidth 800 -PreviewHeight 900`: **5,979 checks passed**, 800×900.
- Both rendered previews were visually inspected. The auto-refill and amount controls fit, the frame stays complete, and native equipment notifications draw above the interface.
- Production AI controller/chest sprites load with genuine alpha at 256×256. The build menu and header use the controller sprite.
- Resource tests cover player-first payment, shortfalls without mutation, duplicate ingredient allocation, stale quantity/metadata rejection, equipment exclusion, exact costs and repeated-payment rejection.
- Patched native methods are exercised for scoped inventory counts, recipe discovery restrictions, alternate-ingredient quality and batch output, normal resource consumption and alternate-ingredient payment.
- Direct native consumption from a chest works with a full player inventory; non-consumables remain untouched.
- An isolated native network stack exercises actual owner-side smelter, fireplace, cooking-station and shield-generator RPCs. Accepted fuel/input additions remove exactly one resource. Full/fractional fuel, full queues/slots, incompatible inputs and non-owner actions leave resources unchanged. Automatic cooking inputs are rejected.
- Existing inventory movement/conservation, pedestal registration, bundle loading, equipped highlights, chest lease expiry and frame clearance diagnostics still pass.

Tests use inactive synthetic objects, temporary inventories and a separate save directory. They do not open or modify an existing character/world. Vanilla reference sprites and decompiled inspection files remain excluded from the repository and release ZIP.

The author previously tested 0.2.4 in co-op. **Live crafting/building/refill tests across multiple peers and a dedicated server are still required for 0.3.0.** Follow `COOP-CHECKLIST.md` before publishing this update.
