# 0.3.2 performance fix validation

Validated on 2026-10-12 against the installed Valheim managed assemblies and Unity 6000.0.75f1, using BepInEx 5.4.23.5.

`test-isolated.ps1`: **6,241 checks passed** in a separate hidden headless process at idle priority. Its executable and BepInEx files, configuration, logs and temporary saves are separate; game assets and the Mono runtime are read through directory junctions. The live game process remained running, and its installed DLL retained the published 0.3.1 hash.

The production native fixture uses 60 loaded synthetic chests holding 3,000 real item stacks, a controller, a player and a native ward. Recorded timings:

| Work | Time | Additional controller searches/cache refreshes |
| --- | --- | --- |
| First availability refresh over all 60 chests | 5.02 ms | One initial refresh |
| 20,000 building availability reads through patched native inventory methods | 5.87 ms | 0 / 0 |
| 5,000 native recipe checks with four requirements (20,000 counts) | 7.39 ms | 0 / 0 |
| Previous per-query inventory traversal alone, 20,000 counts | 1,007.13 ms | Excludes the removed scene searches |
| 5,000 native alternate-ingredient recipe previews | 73.09 ms | 0 / 0 |
| 20,000 refill hover reads | 11.48 ms | 0 controller searches; formatted text reused |

The recipe stress case was about 136 times faster than the previous inventory traversal alone. These are synthetic query timings, not measured FPS in the user's world. No profiling or patching was performed inside the running game.

Additional checks verify indexed counts against linear reference totals for item name, quality, world level, equipped items and empty stacks; immediate invalidation after native inventory changes; movement and negative controller lookup caching; station versus player range; death; periodic exclusion of leased chests; native ward grants, revocation and disabling; and scope restoration after repeated native calls. Actual payment and network authorization paths use fresh permissions and inventories, outside the UI availability cache.

Existing storage conservation, equipment, recipe discovery, alternate-ingredient quality/payment, direct consumption, station capacity, shared switches, protected woods, bundle and UI structure checks still pass. The visual assets/layout are unchanged from the previously inspected 0.3.1 previews. Live gameplay and co-op validation of this performance fix remain pending.
